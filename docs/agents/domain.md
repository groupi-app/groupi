# Domain Docs

Groupi uses a single context shared by its backend, web, mobile,
and shared packages.

## Read before exploring

- Read root `GLOSSARY.md` for domain vocabulary and relationships.
- Read relevant decisions under root `docs/adr/`.

If these documents are absent, proceed silently. Domain modeling
creates them lazily as terminology and decisions are resolved.

## Apply the documented model

Use the terms defined in `GLOSSARY.md` when naming concepts in
tickets, proposals, code, and tests.

When a needed concept is missing, check existing project language
before introducing a term. Record genuine gaps for domain modeling.

If a proposal contradicts an ADR, identify that decision and
explain why it should be reconsidered.
